# v1.0 操作与维护

当前仓库名是「个人知识库-T」。Mac 的「随手记灵感」使用 `⌃⌥⌘I`，把文本存到 `00_收件箱`。「导入小红书」使用 `⌃⌥⌘X`，把一条公开笔记链接交给 Obsidian，完成后打开 `01_资料来源` 的笔记。遇到小红书没有提供正文或媒体时，来源笔记标记待补录。两个快捷指令都可从 Mac 菜单栏打开。

## 从新资料到可复用知识

打开本库的「开始使用」。文字和普通链接先收进 `00_收件箱`；归档后源笔记和收件互链。打开来源执行「查看当前资料的关联候选」，先读原件与候选原文。决定是相同内容、新案例、补充、冲突，还是暂时无可靠关联。不能仅凭分数盖章。没有可靠依据时留待核实或建立新主题，不硬接无关笔记。

标准小红书插件接收原始分享链接并下载媒体。来源 ID 以平台笔记 ID 为准，重复归档复用文件。适配后的原始视频和机器口播在一页，`03 整理版口播` 可人工校正。重跑只修改经哈希核验的机器区块；发现机器区被改动会停止。原始识别 JSON、媒体、拆解证据和人写的整理版分开。找不到原件时按权限获取合法本地媒体，用 `小红书导入.py attach-media SOURCE LOCAL_FILE --reason "合法媒体来源"`，可对普通来源使用。已有原件仍保留，新版本需复核分析。图文不需要执行转写。

对象以文件和属性表示：来源 `type: source`，知识/想法/洞察 `type: note` 与相应 `kind`，关系/演化各有独立记录。下列命令均从 Vault 根目录执行，示例中的路径与摘录要换成真实值：

```sh
python3 99_系统/程序/知识关系.py suggest '01_资料来源/源.md'
python3 99_系统/程序/知识关系.py relate '02_知识笔记/结论.md' '01_资料来源/源.md' supports --evidence '01_资料来源/源.md' '原文中实际出现的至少八字' --reason '为何支持'
python3 99_系统/程序/知识关系.py propose '02_知识笔记/旧观点.md' --evidence '01_资料来源/源.md' '核验过的原文摘录' < 新主张.txt
python3 99_系统/程序/知识关系.py confirm '建议的完整ID' --reason '本人确认依据'
python3 99_系统/程序/知识关系.py health --similar
```

正式关系包含两端 ID、原文摘录、证据文件哈希、类型、状态和时间。演化另存修订版、变化和旧版链接。健康检查默认本地；`--probe` 才访问公开来源，平台拦截或登录页只表示暂不可核验。相似扫描为候选，当前最多扫描前 80 条知识，冲突指已经标注的相互矛盾关系。

## 创作、审核、个人历史

1. 新建或选现有项目，明确形式、受众和要给观众的结果。
2. `创作上下文.py build "选题" --project PROJECT --kind script --audience "受众" --goal "目标" --ref SOURCE`。打开包列出的原文及相关定稿；看原稿结构、近期改法和它们是否适用。没有合适定稿时，只在本人同意后使用 `--continue-without-history "实际同意的理由"`。
3. `知识库.py output PROJECT script --context-id ID --ref SOURCE --used PATH < 草稿.md`。大纲、分镜、文章同样走这一门槛。`--ref` 是实际证据链接，`--used` 用于实际采用的样本、反馈和方法。包记录搜索方式、来源、版本、哈希和引用快照；正式草稿保存时校验当前源文件仍与包一致。局部修改在建包时提供 `--revision OLD --replace-exact "唯一原句"`，stdin 只传替换段。
4. `稿件核查.py OUTPUT` 校验包和实际引用，人工判断不能由程序代替。独立审核用 `知识库.py output PROJECT review --ref OUTPUT < 审核.md`。对已经审核的文件直接改正文，会令旧审核失效。只有本人确认时执行 `知识库.py approve OUTPUT --confirmed "明确确认的依据"`，另存正式快照。
5. 已有历史 Markdown 的登记方式：`创作上下文.py history --project PROJECT --kind script --file /绝对路径/原稿.md --title "作品标题" --audience "受众" --confirmed "本人已确认定稿"`。它保存原始字节和供检索的已确认快照。只有真实个人历史进入这一步；演示样本和外部作品不进入。建议先选 2–4 篇自己认可、形式不完全一样的稿子，每篇补一句为什么认可。
6. `创作上下文.py memory revision|quality|style|method|external-method --title "事项" --confirmed "本人确认理由" --target PATH < 反馈.md`。`quality` 另给 `--quality preferred|accepted|needs_revision|rejected`；个人风格和方法写适用条件；修改反馈加 `--previous OLD` 时还会保存两份稿的原文差异。外部方法仅明确确认后进入已采纳方法，继续保留出处，不变成个人历史。

`log.md` 是只追加的全库总账。系统操作、知识演化、创作记录分别可在 `99_系统/_运行数据/日志/系统日志.md`、`02_知识笔记/_演化/知识成长记录.md`、`99_系统/创作记忆/创作记录.md` 查看。相关确认记忆参与建包；整份系统日志不喂给创作。

## 迁移与恢复

- 本机验证环境：Apple Silicon、Obsidian 1.14.5、Python 3.14、Xiaohongshu Importer 1.1.3。正常浏览不需要 Python。普通工具依赖 `99_系统/依赖.txt`，混合检索环境以 `99_系统/依赖-本地模型.txt` 记录；在另一个 macOS 兼容 Python 3.14 环境可用 venv 安装。恢复后检查 `.obsidian/plugins/kb-local-tools/data.json` 的 `python` 是可执行绝对路径。
- 标准插件源码与发行版保持一致，迁移时从 [标准发行版 1.1.3](https://github.com/bonchiang96/xiaohongshu-importer/releases/tag/1.1.3) 或已验证备份恢复。Obsidian 的本地桥接插件源码在 `99_系统/插件源码`；复制 `main.js`、`manifest.json` 到 `.obsidian/plugins/kb-local-tools` 并在当前库启用。原插件导入目录使用 `00_收件箱/_小红书原始导入`，同目录下媒体下载开启。私有原始暂存区和媒体不进 Git。
- 完整安装包适用于 Apple Silicon Mac 和 macOS 15 或更新版本，随包提供 `whisper.cpp 1.9.5`、AVFoundation 媒体工具、Whisper Small Q5_1 和 multilingual-e5-small。运行「安装.command」后，工具位于 `~/Library/Application Support/personal-knowledge-base-t/bin`，权重位于同目录下的 `models`。初次安装 Python 和依赖需要联网。
- 视频转写在本机运行。存在 FFmpeg 时优先用它提取音轨，否则使用随包的 AVFoundation 工具。语义检索使用 [Xenova multilingual-e5-small 固定版本](https://huggingface.co/Xenova/multilingual-e5-small/tree/761b726dd34fb83930e26aab4e9ac3899aa1fa78)，模型和分词器安装在 `models/e5-small`。两个功能都无按次调用费。
- Whisper 模型 SHA-256 `ae85e4a935d7a567bd102fe55afc16bb595bdb618e11b2fc7591bc08120411bb`；E5 tokenizer `0b44a9d7b51c3c62626640cda0e2c2f70fdacdc25bbbd68038369d14ebdf4c39`；E5 ONNX `f80102d3f2a1229f387d3c81909990d8945513e347b0eab049f7de3c6f98c193`。
- 备份在另一个目录或设备。暂停写入后保存整个 Vault；原件、笔记、日志、分析、转写、配置和上下文快照都要备份。可重建的 SQLite 检索缓存和 Python bytecode 可排除。模型支持目录可另外备份，或按版本和哈希恢复。恢复时先解包到空目录，执行 `知识库.py check`、抽检一份原片和定稿，再决定切换，不覆盖工作库。若归档解包没有还原附加标志，在副本用 `chflags uappnd log.md` 恢复；有三个分账时可对同样设置逐个文件。文件权限和 Git 都不能替代独立备份。
