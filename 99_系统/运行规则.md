# 知识库运行规则

收件时允许只有链接或一段文字。优先从合法公开页面取原文。无法取到就标为 `needs_manual`，写实际原因和手动补录方式。账号登录、验证码和平台权限按正常界面处理。原始 URL 可保存无凭证的引用形式。PDF、视频、图片和其他本地文件保留附件。无正文的附件不能作内容证据。

归档为 `source` 后保留原始内容、作者、收集时间、状态和附件，收件箱有原件入口。来源用规范 URL、平台稳定 ID 或文件哈希去重。不同正文即使标题相同也能共存。YAML 核心字段是 `id`、`type`、`title`、`created`、`updated`、`topics` 和 `status`。来源、关系和项目字段按实际需要填写。日期用 YYYY-MM-DD。手写内容可以先没有 ID，收件归档会生成。

所有可见资料可从 [[05_视图/资料地图]] 进入。写知识页时检索既有资料，至少写一条可以回查的来源或一个明确的作者原始观点。跨笔记关系旁写明它提供的是补证、前置、应用、实测、同源、边界还是反例，以及沿此链接能看到什么。两条同源资料只算一份证据。没有足够依据时写清缺口，先保留在索引里。手工在 Obsidian 新增后，整理时运行 `index` 刷新地图。Bases 则读取实时属性。

阅读时标注原作者观点、已核实事实、用户自己写的内容和 AI 建议。外部研究记录原文链接及核验范围。失败和相互矛盾的来源保留，并在结论旁说明。项目只链接真实用到的资料。

每次创作先检索、读相关知识和原始资料，再读创作规则、风格库、成长日志及最近至多四份正式样本。看具体开头、段落推进、句长和结果如何呈现。素材的事实凭原文，风格来自批准稿与明确反馈。按用户指定阶段产出。审稿优先指出具体哪句话缺证据、哪一镜拍不出来、哪一段可以删。保留历史版本。定稿需要作者明确确认，并记录独立快照和哈希。

成长日志借鉴 Karpathy 的时间序列。写入库、关联、核验、审稿修改、创作方向、定稿、实际复盘和纠错。每次写明实际发生了什么、证据在哪、对下一次有何影响。语气喜好以本人确认或实际正式作品为依据。操作上只通过本地追加命令，macOS 开启追加标志。

参考 [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)。

## v1.0 入库与演化

归档保留原始资料与收件回链；普通网页或本地文件没有可靠正文时标待补录。小红书标准版插件只采集，适配器按平台笔记 ID 归一；正式笔记与日志不保存分享访问参数，标准插件原始暂存区视为私有。视频保存原件哈希、转写版本、带时间的识别、人工整理、证据拆解与关联。

新来源查找相近旧资料，判定重复、新证据、案例、冲突或独立新主题。相似只说明可对读；没有证据不添加正式关系。关系有两个稳定 ID、类型、实证、创建和确认时间。无法判断就留候选。接受更新时追加新版本及差异，保留旧判断和原始证据。

`log.md` 作为总账只追加，同时按事件写入系统日志、知识成长记录或创作记录。索引可重建；原件、逐字稿、作品、确认记录与分析凭证需独立备份。
